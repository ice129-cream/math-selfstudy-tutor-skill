# 在 Claude Code 中使用本 skill

## Claude Code 的装载方式

Claude Code 识别两类东西：项目级记忆文件（约定名 `CLAUDE.md`，放在项目根目录，会作为上下文被读取）和自定义 skill 目录（里面的 `SKILL.md` 按名称 / 描述被识别，命中时加载正文，并可按需读取同目录的其他文件）。本项目的目录结构正好对上第二类：一个 `skills/math-selfstudy-tutor/SKILL.md` 加 `references/` 分册加 `examples/`。

也就是说 Claude Code 是少数几个能比较完整承载本 skill 的平台之一：它的 skill 机制支持"先加载主文件、需要时再打开某个分册"，接近 DSH 的按需加载思路。具体目录位置与扫描规则以所用 Claude Code 版本的文档为准，这里只给通用做法，不假定任何具体菜单或按钮名。

## 安装路径

### 方式一：放进自定义 skill 目录（推荐，保住按需加载）

1. 找到 Claude Code 的自定义 skill 目录（项目级或用户级，按版本约定；项目级放在项目内的约定位置）。
2. 把仓库的 `skills/math-selfstudy-tutor/` 整个目录放进去（复制或软链均可，软链便于仓库更新后自动生效）。
3. 确认 `SKILL.md` 的 frontmatter 完整保留——`name: math-selfstudy-tutor` 和 `description` 里的触发意图（"这题不会""帮我讲""批改我的推导""给道变式""这定理前提是什么""举反例""卡住了"等）决定何时被识别加载。
4. 保持 `references/` 与 `examples/` 相对路径不变，正文里 `references/ladder.md` 这类引用才能按路径打开。

触发后，Claude Code 加载 `SKILL.md` 正文，再按当前信号只取对应分册：进闭环台取 `ladder.md`，进核验台取 `grading.md`，进探究台取 `exploration.md`，学生卡住取 `hints.md`，主动出题则成对取 `sourcing.md` 与 `preflight.md`。这是完整形态，不需要把守则压成一段文本。

### 方式二：写入 CLAUDE.md（没有 skill 目录时的退路）

把 `SKILL.md` frontmatter 以下的正文注入项目根目录的 `CLAUDE.md`，并把 `references/` 目录一并放进工作区保持相对路径可达。agent 会把 CLAUDE.md 当常驻约定，需要细节时按相对路径打开分册。这种方式少了"按名称识别、命中才加载"的自动调度，但仍能读分册，比纯文本粘贴强。

## 调用

自然语言直接说，不造命令：

- "这道题我不会，帮我讲" → 闭环台起步、布置任务、先不主动给提示。
- "我讲给你听这道级数题" → 讲题环节，倾听不打断，讲完再集中拷问。
- "批改我的推导" → 核验台，五维查说理链条，不打√×。
- "换条件会怎样 / 给道变式" → 探究台，先让他自己预判说理再推导验证。
- "自检"这类词只当意图信号，不是要它去跑什么脚本。

## 验证

装好后进会话说一句"这道题我不会，帮我讲"：应进闭环台、布置任务、先不主动给提示，不直接开讲、不给完整推导；说"帮我批改这段推导"应进核验台按五维查说理；回答里杜绝出现守则条目、版本、文件或协议名——行为即导师，不亮工具。

## 核心模式不可削弱

Claude Code 的 skill 机制能保住 references 按需加载，这是它相对 GPTs / Project 的优势。但下面几条是身份本身，无论装载方式如何都不许削弱：

- **三张工作台互斥**：闭环台（默认）、核验台、探究台，按信号进唯一一张，进场明说"现在进 X 模式"，一张台内不混入另一张台的动作。
- **四层闭环以学生输出通关**：独立做题 → 做懂题 → 讲懂题 → 举一反三，层层以学生交出的东西放行，终点是"脱离导师也能讲清楚"，不是听懂或算出答案。
- **自检闸门**：主动出的题发出前独立完整验算、六项全过，不发错题；学生自带真题不触发。
- **不给答案、不泄底**：四层提示梯度，永不泄漏完整推导、不替学生写讲稿。
- **真题为母**：官方真题优先、结构性改编，不凭空造题、不拿来源不明的模拟卷当主素材。

Claude Code 上体验接近完整形态，越是这样，越没有借口弱化上述核心。
